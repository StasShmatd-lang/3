# Фото-охота

Корпоративный интерактив: ведущий задаёт **5 миссий**, гости грузят фото с телефона, хост модерирует, на экране зала — галерея одобренных кадров.

Рабочее приложение: папка **`next-app/`** (Next.js App Router + Postgres / PGlite).

## Быстрый старт

```bash
cd next-app
npm install
env -u DATABASE_URL npm run dev
```

Откройте http://127.0.0.1:3000

## Сценарий

1. **Главная** — создать охоту: название ивента, опционально лого компании, ровно 5 миссий (текст + опциональный референс). Пароль не нужен.
2. **Ведущий** `/host/{id}` — QR на вход гостей, скрыть неудачное фото, ссылка на экран зала.
3. **Гость** `/join/{id}` — сканирует QR, вводит только имя, грузит фото на миссию.
4. **Экран зала** `/screen/{id}#s=…` — рубрики миссий + фото сразу после съёмки (без модерации); токен в hash.

## Доступ и нагрузка (20.11)

- **Без ключей и паролей.** Охоту создаёт любой, кто открыл ссылку приложения (`EVENT_CREATE_SECRET` больше не нужен). Гость заходит по QR и вводит только имя. Ссылка ведущего (с токеном в `#h=`) и экрана зала (`#s=`) по-прежнему личные — их не показывайте гостям.
- **Фото отдельно от события.** Фото, референсы и лого хранятся в таблице `images` (миграция `003_images.sql`) и отдаются по `/api/img/:id` с кэшем браузера. Экран зала при каждом обновлении получает килобайты, а не все фото заново.
- **Одновременные загрузки не теряются.** Изменения события идут в транзакции с блокировкой строки.
- **Лимиты по устройству, а не на весь зал.** Раньше общий лимит блокировал всех уже на 4–5 телефонах.
- Охоты, которые не трогали 7 дней, удаляются вместе с фото автоматически.

## Publish (Cursor Cloud Apps)

Публикуйте папку `next-app` (есть `cursor-app.json` → Postgres). Локально без `DATABASE_URL` используется PGlite.
